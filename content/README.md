# Content files: how a course week is described

Everything Homebase shows comes from these JSON files. They contain only
links, page numbers, labels and our own short descriptions. **Never put
problem text, solution text or book text in them**: that stays in the PDFs
in `library/` (git-ignored, personal study copies). Generated problems are
the exception; their text is written by our own code.

After any edit, run:

```
.venv\Scripts\python scripts\validate_content.py --render <course>
```

It must report 0 errors. Restart Homebase (or run `python -m app.seed`) to load the changes.

## Files per course (`content/<course>/`)

| File | What | Who edits |
|---|---|---|
| `weeks.json`, `videos.json` | Term weeks and lecture videos | Generated by `scripts/build_content.py` from `research/`. Don't hand-edit. |
| `resources.json` | Books, notes, worksheets, solution files | Hand-edited |
| `week01.json` … `week10.json` | Readings and problem sets for each term week | Hand-edited (`ece201/week01.json` is the template) |
| `exams.json` | Timed practice exams | Hand-edited, and **every exam checked by eye** (see below) |
| `ece201/bench.json` | Book exercises drawn on the Circuit Bench (parts and wires only, no book text) | Generated by `node scripts/export_bench_book.mjs`. Don't hand-edit. |

## resources.json

```json
{"id": "kuphaldt-kvl", "kind": "worksheet", "title": "Kuphaldt worksheet: KVL",
 "url": "https://www.ibiblio.org/kuphaldt/socratic/output/kvl.pdf",
 "local_path": "library/ece201/kuphaldt/kvl.pdf",
 "license": "CC BY 1.0 (stated in the worksheet)", "notes": ""}
```

`kind` is one of textbook, notes, slides, worksheet, solutions, reference or problems. `license` is required: write "unknown" plus a note if it isn't stated. Only use URLs you actually opened.

## weekNN.json

```json
{
  "week": 3,
  "readings": [
    {"id": "ece201-w3-ulaby-2-4", "resource": "ulaby-cad3e", "sections": "2-4 and 2-5 (Y-Delta, bridge)", "est_min": 30},
    {"id": "ece201-w3-fiore-5", "resource": "fiore-dc", "sections": "Chapter 5", "page": 141, "est_min": 25, "optional": true}
  ],
  "problem_sets": [ ... ]
}
```

Reading ids must be unique across the whole course. `page` is optional and is the PDF page to open at.

### Problem sets

Every problem points at where it is printed (`statement`) and where its answer is (`key`). Regions are:

| Region | Meaning |
|---|---|
| `{"pdf": "library/...pdf", "page": 16, "start": "Exercise 2-1", "end": "Solution:"}` | Part of one page, between two pieces of text found on it. `end` may be `"A\|B"` (whichever comes first), or `"paragraph"`; use `"end_after"` to include the line with that text. Omit `start` to begin at the top of the page, or `end` to run to the bottom. |
| `{"pdf": "library/...pdf", "pages": [4, 5]}` | Whole pages, stacked |
| `{"images": ["library/ece200/dspfirst-db/ch02/p012s1.png"]}` | Image files, stacked (scanned solutions) |

`key_type` is one of:

| key_type | Meaning |
|---|---|
| `official_worked` | A published worked solution |
| `official_answer` | Published final answers only |
| `computed` | Generated problems only |
| `none` | No key exists. Avoid these where possible; use them only for genuinely useful practice, and note it. |

There are two ways to list problems.

**1. A pattern**, when problems are numbered regularly (see `ece201/week01.json`):

```json
{"id": "ulaby-ex-ch2", "title": "Ulaby chapter 2 exercises", "source": "...", "resource": "ulaby-exercise-sol",
 "problems": {"label": "Exercise 2-{n}", "count": 14, "key_type": "official_worked",
   "statement": {"pdf": "...", "page": "auto:Exercise 2-{n}", "start": "Exercise 2-{n}", "end": "Solution:"},
   "key": {"pdf": "...", "page": "auto:Exercise 2-{n}", "start": "Solution:", "end": "Fawwaz T"}}}
```

`{n}` and `{n+1}` are filled in. A `page` can be a number, an expression like `"15+n"`, or `"auto:<text>"` (the first page containing that text).

**2. A list**, when problems are irregular:

```json
{"id": "dspdb-ch2", "title": "DSP First problems: sinusoids", "source": "...", "resource": "dspfirst-db",
 "problems": [
   {"id": "p012", "label": "Problem 2.12", "key_type": "official_worked", "topics": ["phasors"],
    "statement": {"pdf": "library/ece200/dspfirst-db/ch02/p012.pdf", "page": 1},
    "key": {"images": ["library/ece200/dspfirst-db/ch02/p012s1.png"]}}
 ]}
```

Also on a problem set:
- `"optional": true` for extra practice
- `"notes"`, a sentence shown on the set's page (license caveats, "answers only", and so on)

**The statement region must not show the answer.** If a source prints the answer right under the problem, end the statement region above it. If the answer is interleaved with the problem, don't use that source.

### Labs (ECE 200)

A week can list Python labs:

```json
"labs": [
  {"id": "ece200-lab04", "number": 4, "title": "Lab 4: FIR filters by hand",
   "goal": "Write your own FIR filter loop, check it against np.convolve ...",
   "handout": {"resource": "dspfirst-labs", "pdf": "library/ece200/dspfirst-labs/convolutionFIR.pdf",
               "title": "DSP First Lab S-4: Convolution & FIR Filters"},
   "starter": "labs/ece200/lab04_fir.py", "est_min": 30}
]
```

- `id` must be unique.
- `number` picks the checks in `app/lab_checks/<course>.py` (`CHECKS[number]`).
- `handout` is background reading: a MATLAB handout, a resource in `resources.json`. Its `pdf` must be in `library/`.
- `starter` is our own Python file. Each function it asks for:
  - says what to compute in its docstring
  - has `return None  # TODO` as its body
  - is matched by the checks (which call it through `ask(m, "name", ...)`)

To add or change a lab:
1. Write the starter.
2. Write its checks: compare with NumPy/SciPy using `same(...)`, and use `by_hand(...)` when the function must not call the built-in.
3. Put a worked answer in `tests/lab_answers/<course>/` with the same file name. `tests/test_labs.py` checks that the answer passes every check.

The validator runs the checker on every blank starter, and every check must come back `todo`.

A prep-plan task links to a lab with `"lab": "ece200-lab04"`. The lab tasks also have an explicit `"id"` (the one they had before the link was added), so their done marks are kept.

## exams.json

See `ece201/exams.json`. Per problem, use `pages` + `key_pages`, or `statement` + `key` regions (without `pdf`; it comes from the exam's `exam_pdf` / `key_pdf`). Each problem needs `points`.

**Every exam must be checked by eye before it is added:**
1. Render every page with `python -I scripts/contact_sheet.py <pdf> <out.png> 4`, then look at the image.
2. Confirm the "blank" exam really has no answers written in. Many archive files are solved copies; see `research/exam_audit.txt`.
3. Map each problem to its exam page(s) and solution page(s) by looking at both.
4. Leave out problems outside the course's scope, cut the time in proportion, and say so in `skipped` and `time_note`.
5. Write `"verified": "Checked by eye <date>: ..."`. The validator rejects an exam without "by eye".

Use only exams that have official solutions. `practice_rules` should match the OSU course: closed book, no calculator, plus the note sheet or index card the course allows.
